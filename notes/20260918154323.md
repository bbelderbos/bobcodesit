# A real sentinel builtin in Python 3.15 (PEP 661)

`None` can't double as "not provided" when `None` is itself a valid value. The classic case: an update function where passing `bio=None` means "clear the field" but omitting `bio` means "leave it alone". With `None` as the default you can't tell those apart.

The old fix was `MISSING = object()`. Python 3.15 makes it official — PEP 661 adds a `sentinel` builtin (no import, like `object()` or `None`):

```python
# Python 3.15+, signature: sentinel(name, /, *, repr=None)
MISSING = sentinel("MISSING")

def update_user_profile(user_id: int, bio: str | None | MISSING = MISSING) -> None:
    if bio is MISSING:
        return  # not provided, leave unchanged
    if bio is None:
        db.update(user_id, bio=None)  # explicitly cleared
    else:
        db.update(user_id, bio=bio)
```

The wins over `object()`:

- **It's a type.** Type checkers recognize the `NAME = sentinel("NAME")` pattern, so you can write it straight into the annotation (`str | None | MISSING`) — a plain `object()` can't do that.
- **Nice `repr`** for debugging instead of `<object object at 0x...>`.
- **Picklable** when defined at module level with a matching name.

Two rules: check with `is`, never `==`, and define sentinels at module scope so callers don't spawn a second, unequal instance.
