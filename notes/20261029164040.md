# Run your Rust code in a web page with WebAssembly

You can ship a Rust library to the browser with no server. `wasm-bindgen` exports the functions you mark, and `wasm-pack` compiles them to a `.wasm` file plus the JS glue that loads it. I used this for a [JSON playground](https://bbelderbos.github.io/json_parser/) for my parser, hosted on GitHub Pages.

1. Make the crate a cdylib and add wasm-bindgen behind a feature, so normal Rust users of the crate don't pull it in:

```toml
[lib]
crate-type = ["cdylib", "rlib"]

[dependencies]
wasm-bindgen = { version = "0.2", optional = true }

[features]
wasm = ["wasm-bindgen"]
```

2. Write a thin wrapper in its own module, gated with `#[cfg(feature = "wasm")] mod wasm_bindings;` in `lib.rs`. This is the only part you write. Stick to simple types (`&str` in, `String` out). Returning `Err(JsValue)` turns into a thrown JS exception:

```rust
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn parse_json_wasm(input: &str) -> Result<String, JsValue> {
    parse(input)
        .map(|value| value.to_string())
        .map_err(|e| JsValue::from_str(&e.to_string()))
}
```

3. Build for the browser and copy the output into your static site. Copy instead of building straight into `docs/`, because wasm-pack drops a `.gitignore` containing `*` in its output dir:

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-pack
wasm-pack build --target web --out-dir pkg -- --features wasm
cp pkg/rust_json_parser.js pkg/rust_json_parser_bg.wasm docs/wasm/
```

4. Load it from an ES module. `init()` fetches and instantiates the `.wasm`; after that the export behaves like a normal JS function:

```html
<script type="module">
import init, { parse_json_wasm } from "./wasm/rust_json_parser.js";
await init();

try {
  const out = parse_json_wasm('{"online": true}');
  console.log(JSON.parse(out));
} catch (err) {
  console.error("Rust said:", err);
}
</script>
```

The generated `rust_json_parser.js` is the wasm-bindgen equivalent of what pyo3 generates for Python: WebAssembly functions only take numbers, so the glue copies your string into wasm memory as UTF-8, calls the export with a pointer and length, decodes the result and frees the memory. Don't edit it, it gets overwritten on every build.

Gotchas: it needs `type="module"`. Inline `onclick` handlers can't see module-scoped functions, so assign them with `window.fn = fn`. Opening the page as `file://` fails because the `.wasm` fetch is blocked, so serve it (`python -m http.server`) or use GitHub Pages. Commit the wrapper and the build command too, not just the generated files, or you can't rebuild them later. If your `<user>.github.io` repo has a custom domain, every project page redirects there too, so `/json_parser/` 404'd on my old domain until I removed it.
