# Custom QuerySet as a Django manager for reusable, chainable filters

Ever seen a bunch of views in Django repeating the same query logic (e.g. `Model.object.filter`)?

A nice abstraction is "model managers" where you can push this to the model. 

Not only will make it your code more DRY, you'll also get a more readable interface, e.g. `Habit.objects.active()`.

Which you can even chain, e.g. `Habit.objects.filter(user=u).active_on(day)`. 

The query intent lives on the model, and callers read like the domain.

```python
from datetime import date

from django.conf import settings
from django.db import models
from django.db.models import Q


class HabitQuerySet(models.QuerySet):
    def active(self):
        return self.filter(archived_at__isnull=True)

    def active_on(self, day: date):
        return self.filter(
            Q(start_date__lte=day)
            & (Q(archived_at__isnull=True) | Q(archived_at__date__gte=day))
        )


class Habit(models.Model):
    user = models.ForeignKey(
        settings.AUTH_USER_MODEL, on_delete=models.CASCADE, related_name="habits"
    )
    name = models.CharField(max_length=100)
    start_date = models.DateField(default=date.today)
    archived_at = models.DateTimeField(null=True, blank=True)

    objects = HabitQuerySet.as_manager()  # ty: ignore[missing-argument]


# chainable + reusable (illustrative — assumes a bound `user`)
Habit.objects.active()
Habit.objects.filter(user=user).active_on(date.today())
user.habits.active()  # works across the reverse relation too
```
