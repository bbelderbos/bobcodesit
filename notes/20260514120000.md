# Handle the same scenario the same way

I reviewed code where "no results" raised `typer.Exit()` in one branch but just printed a message in another. Same condition, different behavior. Confusing for users and maintainers alike.

This principle from Code Complete: "use consistent levels of abstraction."

```python
# Inconsistent - different handling for same "no results" scenario
def search(query: str, titles_only: bool = False):
    results = find_results(query, titles_only)

    if titles_only and not results:
        print(f"No match for {query}")  # Just prints, continues
    elif not results:
        print(f"No match for {query}")
        raise typer.Exit()  # Exits!

# Consistent - same scenario, same handling
def search(query: str, titles_only: bool = False):
    results = find_results(query, titles_only)

    if not results:
        print(f"No match for {query}")
        raise typer.Exit()

    display_results(results)
```

When similar conditions behave differently without a clear reason, it masks bugs and confuses readers. Pick a pattern and stick to it.
