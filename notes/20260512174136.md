# contextlib.nullcontext keeps `with` branches symmetric

When one branch of an `if` needs a real context manager and the other doesn't, you usually end up duplicating the body just to keep the `with` block in one branch. `contextlib.nullcontext()` is the stdlib's no-op context manager — its `__enter__` returns whatever you pass in (default `None`), its `__exit__` does nothing. So you can pick the context manager up front and run a single `with` block.

```python
from contextlib import nullcontext
from typing import Protocol


class Repo(Protocol):
    def save(self, item: str) -> None: ...


class DBRepo:
    def __enter__(self) -> "DBRepo":
        print("open connection")
        return self

    def __exit__(self, *exc) -> None:
        print("close connection")

    def save(self, item: str) -> None:
        print(f"persist {item}")


def run(item: str, db_url: str | None) -> None:
    repo_ctx = DBRepo() if db_url else nullcontext()
    with repo_ctx as repo:
        if repo:
            repo.save(item)
        else:
            print(f"dry run: {item}")


run("apple", db_url="sqlite:///x.db")
# open connection
# persist apple
# close connection

run("apple", db_url=None)
# dry run: apple
```

Without `nullcontext`, you'd duplicate the block body across both `if` branches — or wrap an `if repo is not None` around every use. This keeps cleanup deterministic on the db path and is a clean no-op on the other.
