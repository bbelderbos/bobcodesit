# Rust's `?` operator: a one-character try/except

The intuition: *"I expect this to work; if it doesn't, we're done here."* The `?` operator lets you say that in one character, so the code stays focused on business logic instead of error-handling mechanics.

In Python, propagating an error through a chain of calls usually looks like this:

```python
def parse_score(s: str) -> int:
    try:
        n = int(s.strip())
    except ValueError as e:
        raise ValueError(f"'{s.strip()}' is not a valid number") from e
    if n > 100:
        raise ValueError(f"{n} is out of range (0-100)")
    return n
```

Errors propagate via exceptions, which the function signature does not advertise. Callers find out at runtime.

Rust puts the failure right in the return type with `Result<T, E>`, and the `?` operator does the unwrap-or-return-the-error dance in one character:

```rust
fn parse_score(s: &str) -> Result<u32, String> {
    let n: u32 = s
        .trim()
        .parse()
        .map_err(|_| format!("'{}' is not a valid number", s.trim()))?;
    if n > 100 {
        return Err(format!("{} is out of range (0-100)", n));
    }
    Ok(n)
}
```

That trailing `?` reads as: "if this is `Err`, return it from the function; otherwise, give me the value." No try/except scaffolding, and the signature tells you exactly what can fail.

Without `?`, every fallible call needs an explicit `match` to propagate — verbose and noisy:

```rust
// Without ? - verbose error propagation
fn parse_json(input: &str) -> Result<JsonValue, JsonError> {
    let tokens = match tokenize(input) {
        Ok(t) => t,
        Err(e) => return Err(e),
    };
    let value = match parse_tokens(&tokens) {
        Ok(v) => v,
        Err(e) => return Err(e),
    };
    Ok(value)
}

// With ? - clean and focused
fn parse_json(input: &str) -> Result<JsonValue, JsonError> {
    let tokens = tokenize(input)?;
    let value = parse_tokens(&tokens)?;
    Ok(value)
}
```

Closest Python analogy: `result.unwrap()` style libraries (`returns`, `result`), but `?` is built into the language.
