# Guard clauses beat the arrow anti-pattern

How to avoid deeply nested code (the notorious arrow shape)?

Use early returns (guard clauses).

The biggest win isn't just cleaner aesthetics, it’s less cognitive load.

Edge cases are immediately cleared at the top instead of accumulating nested conditions in your head. 

In the example below, it also documents each error condition better:

```python
# ❌ The Arrow: Pushes business logic off the screen
def refund_transaction(user: User, tx: Transaction) -> Refund:
    if user.is_admin:
        if tx.status == "completed":
            if not tx.is_refunded:
                return execute_refund(tx)
    raise ValueError("Invalid refund request")

# ✅ Early Returns: Clears roadblocks first, keeps happy path flat
def refund_transaction(user: User, tx: Transaction) -> Refund:
    if not user.is_admin:
        raise PermissionError("User is not authorized to issue refunds")
    if tx.status != "completed":
        raise ValueError("Cannot refund an incomplete transaction")
    if tx.is_refunded:
        raise ValueError("Transaction has already been refunded")

    # Happy path sits cleanly at the bottom
    return execute_refund(tx)
```
