# SQLAlchemy: closing a session is not the same as disposing the engine

Common gotcha. You wrap your repo with `__enter__`/`__exit__`, call `session.close()`, and assume cleanup is done. It isn't. `session.close()` returns the checked-out connection to the engine's *pool*. The pool is owned by the engine. Until the engine is disposed (or garbage collected), the pool keeps connections open.

```python
from sqlalchemy import create_engine
from sqlmodel import Session, SQLModel


class DBRepo:
    def __init__(self, db_url: str) -> None:
        self._engine = create_engine(db_url)
        SQLModel.metadata.create_all(self._engine)
        self._session = Session(self._engine)

    def __enter__(self) -> "DBRepo":
        return self

    def __exit__(self, *exc) -> None:
        self.close()

    def close(self) -> None:
        if self._session:
            self._session.close()       # returns connection to pool
        if self._engine is not None:
            self._engine.dispose()      # actually releases pool resources
```

Symptoms when you forget `engine.dispose()`:

- `ResourceWarning: unclosed database in <sqlite3.Connection ...>` in pytest
- File handles or DB connections accumulating in long-running processes
- pytest's `unraisableexception` plugin firing between tests (it runs `gc.collect()` and catches the still-open connection)

SQLAlchemy registers a weakref finalizer that disposes the pool when the engine is GC'd, so things often "look fine" — until they don't. GC timing isn't deterministic. Don't rely on it; dispose explicitly.

Rule of thumb: if a class creates the engine, the same class is responsible for disposing it. Or — better — don't let the repo own the engine at all; inject the session from outside and keep the engine as a single process-level resource.
