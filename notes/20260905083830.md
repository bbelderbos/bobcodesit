# Django middleware to DRY out a per-request concern

Same instinct as a custom model manager: when the *same little thing* has to happen on every request, hoist it into one place instead of copy-pasting it into every view.

I hit this with a habit tracker. Check-offs were landing on the wrong day: `timezone.localdate()` resolves against the *active* timezone, which on the server was UTC — so an evening check-in in Spain (UTC+2) rolled back to "yesterday". Each user needed their own timezone applied before any `localdate()` ran.

The wrong fix is `timezone.activate(...)` at the top of every view. The right fix is one middleware — it runs on every request, sees `request.user`, and all the existing `localdate()` calls just work unchanged:

```python
# tracker/middleware.py
from zoneinfo import ZoneInfo, ZoneInfoNotFoundError
from django.utils import timezone
from .models import Profile


class TimezoneMiddleware:
    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        tzname = None
        if request.user.is_authenticated:
            tzname = (
                Profile.objects.filter(user=request.user)
                .values_list("timezone", flat=True)
                .first()
            )
        if tzname:
            try:
                timezone.activate(ZoneInfo(tzname))
            except (ZoneInfoNotFoundError, ValueError):
                timezone.deactivate()
        else:
            timezone.deactivate()
        return self.get_response(request)
```

Register it after `AuthenticationMiddleware` (you need `request.user`):

```python
MIDDLEWARE = [
    # ...
    "django.contrib.auth.middleware.AuthenticationMiddleware",
    "tracker.middleware.TimezoneMiddleware",
    # ...
]
```

The `__init__`/`__call__` shape *is* the whole contract: `get_response` is handed in once at startup, and you do your work around calling it per request. Storing the timezone on a `Profile` is just data — nothing consults it automatically; the middleware is what turns that stored value into behavior. Same DRY payoff as a manager: define once, applies everywhere.
