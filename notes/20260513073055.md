# Squash all git history into one clean commit

Going public with a private repo? Your `.gitignore` only protects the working tree — anything you *used* to commit (marketing notes, draft secrets, embarrassing early commits) is still recoverable from history with `git show <sha>:path`.

The cleanest fix is an **orphan branch**: start a new root commit with the current tree, then replace `main`.

```bash
# 1. Audit history first — what's recoverable that shouldn't be?
git log --all --name-only --pretty=format: | sort -u
git grep -nIE "(sk-ant|api[_-]?key|secret|token)" $(git rev-list --all)

# 2. Orphan branch = no parent, fresh root
git checkout --orphan clean-main
git add -A
git commit -m "init: public release"

# 3. Replace main locally
git branch -D main
git branch -m main

# 4. Overwrite remote (destructive — confirm first)
git push -f origin main
```

The working tree is unchanged — only history is rewritten. `.gitignore` rules still apply, so files like `linkedin.md` or `.env` that were ignored at HEAD won't sneak back in via `git add -A`.

**Caveats:**
- Anyone who cloned before will have a divergent fork. Fine for solo / pre-public repos, painful for shared ones.
- If secrets actually leaked to a public remote, rotate them — rewriting history doesn't un-leak what was already scraped.
- For surgical edits (drop one file across history, keep the rest), reach for `git filter-repo` instead.
