# Promote ResourceWarning to a hard test failure

Once you've fixed a connection / file / socket leak, lock it in. pytest swallows `ResourceWarning` by default, so a regression won't break CI — it'll just print a polite note nobody reads. Two ways to turn it into a real failure:

**One-off CLI flag** — handy during debugging:

```bash
uv run pytest -W error::ResourceWarning
```

**Permanent, project-wide** — put it in `pyproject.toml` so every CI run enforces it:

```toml
[tool.pytest.ini_options]
filterwarnings = [
    "error::ResourceWarning",
]
```

Or in `pytest.ini` if you're not using `pyproject.toml`:

```ini
[pytest]
filterwarnings =
    error::ResourceWarning
```

Now any unclosed connection, file, or socket fails the test that triggered it — with a real traceback — instead of a warning at the end of the run. Pair it with `PYTHONTRACEMALLOC=20` when something does break, so you get the allocation site too.

Same trick works for any warning category: `DeprecationWarning`, `PendingDeprecationWarning`, your own `UserWarning` subclasses. Useful for catching deprecations before the upstream library actually removes the API.
