# Skip pip with a stub file on sys.path (Pyodide trick, also works elsewhere)

`pip` / `micropip` is just a download tool — it fetches files and drops them on `sys.path`. The Python interpreter itself doesn't know or care about pip. At import time, it walks `sys.path` directories and grabs the first `<name>.py` or `<name>/__init__.py` it finds.

Means: you can shadow any package by writing a file to a directory that's earlier on `sys.path`. No pip install needed.

Hit this building the agentic AI funnel: every exercise does `import anthropic` + `anthropic.Anthropic()`, but every test mocks the class via `patch("solution.anthropic.Anthropic")`. The real SDK was 5MB+ across deps and added ~3s to Pyodide boot. A 4-line stub does the job:

```python
# In Pyodide's in-browser FS:
pyodide.FS.writeFile("/home/pyodide/anthropic.py", """\
class Anthropic:
    def __init__(self, *args, **kwargs):
        pass
""")

# In the test runner:
sys.path.insert(0, "/home/pyodide")
# Now `import anthropic` finds the stub before anything else.
# patch("solution.anthropic.Anthropic", return_value=mock_client) replaces it.
# The stub's body never actually runs.
```

Use this when:
- The real package is heavy and you only need the *name* to resolve (tests mock the class)
- You're in a constrained env (Pyodide, AWS Lambda layers, embedded) and want to skip an install
- Quick local repro where the real package is finicky to set up

When NOT to: you actually need the package's behavior. Stubbing hides type errors and silently passes things that would fail in prod.
