# `Option<T>` in Rust: the end of `AttributeError: 'NoneType' object has no attribute 'x'`

If you've shipped Python long enough, you've been paged for this:

```python
user = get_user(user_id)  # returns User | None
print(user.name)          # AttributeError at 3am
```

Type hints help, but nothing *forces* you to handle the `None`. Rust does. There is no `null`. A function that might not return a value returns `Option<T>`, which is either `Some(value)` or `None`, and the compiler will not let you use the inner value without unpacking it first.

```rust
fn first_word(s: &str) -> Option<&str> {
    s.split_whitespace().next()  // already Option<&str>
}

// Caller is forced to handle both branches:
let word = first_word("").unwrap_or("(empty)");

// Or pattern match:
match first_word(text) {
    Some(w) => println!("first word: {w}"),
    None    => println!("no words"),
}
```

The mindset shift: "missing" becomes part of the type, not a runtime surprise. Same idea as Python's `Optional[T]`, except the compiler actually enforces it.
