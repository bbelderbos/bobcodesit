# bool.then(|| ...) flattens the happy path in Rust iterator chains

Inside `filter_map`, when you parse something and then want to keep it only if a condition holds, the obvious way is `if/else` with `Some`/`None`:

```rust
.filter_map(|record| {
    let (name, score_str) = record.split_once(':')?;
    let score: u32 = score_str.trim().parse().ok()?;
    if score >= threshold {
        Some((name.trim().to_string(), score))
    } else {
        None
    }
})
```

Works, but the four-line `if/else` breaks the flow. `bool::then` turns a bool into an `Option` in one line:

```rust
.filter_map(|record| {
    let (name, score_str) = record.split_once(':')?;
    let score: u32 = score_str.trim().parse().ok()?;
    (score >= threshold).then(|| (name.trim().to_string(), score))
})
```

`true.then(|| x)` returns `Some(x)`, `false.then(|| x)` returns `None`. The closure is lazy too, so the body only runs when the condition holds (matters if it allocates, like `to_string()` here).

There's also `.then_some(value)` for eager values, no closure. Use that when the value is cheap (a literal, a `Copy` field). Reach for `.then(|| ...)` when you'd otherwise pay for allocation in the `false` branch.

Same idea as Python's `value if cond else None`, but it composes with the rest of an iterator chain.
