# Where did that unclosed DB connection come from? Stop guessing. 🕵️

Ever hit `ResourceWarning: unclosed database` while running pytest?

Standard Python warnings tell you where the object **died** — usually some random GC cycle, far from the actual bug. But what if you need to know where it was **born**?

Follow the hint in the error: *"Enable tracemalloc to get the object allocation traceback."*

```bash
PYTHONTRACEMALLOC=20 uv run pytest tests/ -W default
```

(The `20` is frame depth — bump it if your stack goes deeper.)

Now instead of a vague warning, you get a traceback pointing right at the source. In my case, a `DBExpenseRepository` allocated inside a conditional that skipped the `with` block.

The fix? `contextlib.nullcontext()` keeps both branches under a single `with`:

```python
repo_ctx = DBExpenseRepository(db_name) if db_name else nullcontext()
with repo_ctx as repo:
    ...
```

Single `with` block, deterministic cleanup on both branches.

Bonus: re-run with `-W error::ResourceWarning` to turn the warning into a hard test failure — so it can't sneak back in.
