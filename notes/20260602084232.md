# Rust feels verbose until you reach for the iterator chain

Rust gets called verbose, and the imperative version of "dedupe a list" backs that up: a result vec, a `HashSet`, a manual loop, an `if !contains` guard, two pushes. Compare it to the Python one-liner and Rust looks like a lot of ceremony.

But the functional style closes most of that gap. The trick is that `HashSet::insert` returns a `bool` — `true` if the value was newly added — so it doubles as both the "have I seen this?" check and the record of having seen it. Drop that straight into a `filter` and the whole thing collapses to one line.

```rust
use std::collections::HashSet;

// verbose: manual loop + separate seen-check and insert
fn unique_items(items: Vec<i32>) -> Vec<i32> {
    let mut ret = Vec::new();
    let mut seen = HashSet::new();
    for i in &items {
        if !seen.contains(i) {
            ret.push(*i);
        }
        seen.insert(i);
    }
    ret
}

// concise: insert() returns true on first sight, so it filters and records at once
fn unique_items(items: Vec<i32>) -> Vec<i32> {
    let mut seen = HashSet::new();
    items.into_iter().filter(|x| seen.insert(*x)).collect()
}
```

Mutating `seen` inside a `filter` might look sketchy — isn't a predicate supposed to be pure? In Rust it's fine: `filter` takes an `FnMut`, not an `Fn`, so mutation is explicitly allowed, and iterators are single-pass, so each item flows through the closure exactly once. This is idiomatic enough that `itertools::unique` does the same thing internally.

The Python equivalent is `list(dict.fromkeys(items))`. Rust won't always match that for length, but method chaining over iterators gets it close — and you keep the type safety and zero-cost abstraction for free.
